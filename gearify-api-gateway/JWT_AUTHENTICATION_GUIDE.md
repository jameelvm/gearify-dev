# API Gateway JWT Authentication Guide

**Last Updated**: November 26, 2025
**Version**: 1.0

---

## Overview

The API Gateway now properly validates JWT access tokens issued by the Gearify Auth Service. This guide explains the authentication flow, configuration, and how to test it.

## Architecture

```
┌─────────────────────────────────────────────────────────────────────┐
│                    AUTHENTICATION FLOW                              │
└─────────────────────────────────────────────────────────────────────┘

Client
  │
  ├─ POST /api/auth/login
  │  └─> API Gateway (YARP) → Auth Service
  │      Auth Service generates:
  │        - Access Token (JWT, 15 min expiry)
  │        - Refresh Token (random string, 7 day expiry)
  │      Returns: { token, refreshToken, user }
  │
  ├─ GET /api/catalog/products
  │  Headers: Authorization: Bearer <JWT>
  │  └─> API Gateway
  │      ┌──────────────────────────────────────────────┐
  │      │ JWT Validation (Program.cs:82-126):         │
  │      │                                              │
  │      │ 1. Extract JWT from Authorization header    │
  │      │ 2. Validate signature with shared secret    │
  │      │ 3. Validate issuer: "gearify-auth"          │
  │      │ 4. Validate audience: "gearify-api"         │
  │      │ 5. Validate expiration (15 minutes)         │
  │      │ 6. Extract claims (userId, tenantId, role)  │
  │      │                                              │
  │      │ IF VALID: Forward request to service        │
  │      │ IF EXPIRED: Return 401 + "Token-Expired"    │
  │      │ IF INVALID: Return 401 Unauthorized         │
  │      └──────────────────────────────────────────────┘
  │
  │      → Forward to Catalog Service ✅
  │
  └─ Access Token Expired? Use Refresh Token
     POST /api/auth/refresh
     { refreshToken: "..." }
     └─> Returns new access token + new refresh token
```

## Configuration

### Shared JWT Secret

**CRITICAL**: The API Gateway and Auth Service MUST use the **same JWT secret**.

#### Auth Service (`gearify-auth-svc/appsettings.json`):
```json
{
  "JwtSettings": {
    "Secret": "your-super-secret-jwt-key-that-is-at-least-32-characters-long-for-security",
    "Issuer": "gearify-auth",
    "Audience": "gearify-api",
    "AccessTokenExpiryMinutes": 15,
    "RefreshTokenExpiryDays": 7
  }
}
```

#### API Gateway (`gearify-api-gateway/appsettings.json`):
```json
{
  "JwtSettings": {
    "Secret": "your-super-secret-jwt-key-that-is-at-least-32-characters-long-for-security",
    "Issuer": "gearify-auth",
    "Audience": "gearify-api"
  }
}
```

### JWT Validation Parameters

From `Program.cs` (lines 85-95):

```csharp
options.TokenValidationParameters = new TokenValidationParameters
{
    ValidateIssuerSigningKey = true,    // Validate signature
    IssuerSigningKey = new SymmetricSecurityKey(key),
    ValidateIssuer = true,               // Validate issuer
    ValidIssuer = "gearify-auth",
    ValidateAudience = true,             // Validate audience
    ValidAudience = "gearify-api",
    ValidateLifetime = true,             // ← Validates expiration!
    ClockSkew = TimeSpan.Zero            // No grace period
};
```

**Key Points**:
- `ValidateLifetime = true` → Checks token expiration
- `ClockSkew = TimeSpan.Zero` → No grace period (strict 15-minute expiry)

## Token Structure

### Access Token (JWT)

Generated by Auth Service (`JwtService.cs`):

```
Header:
{
  "alg": "HS256",
  "typ": "JWT"
}

Payload (Claims):
{
  "sub": "usr_123",                    // User ID
  "email": "john@example.com",
  "jti": "guid-unique-id",
  "tenantId": "default",
  "role": "Customer",
  "firstName": "John",
  "lastName": "Doe",
  "iss": "gearify-auth",              // Issuer
  "aud": "gearify-api",               // Audience
  "exp": 1732630800,                   // Expiration (Unix timestamp)
  "iat": 1732629900                    // Issued at
}

Signature:
HMACSHA256(
  base64UrlEncode(header) + "." +
  base64UrlEncode(payload),
  secret
)
```

**Expiration**:
- `exp` claim is set to: `DateTime.UtcNow.AddMinutes(15)`
- API Gateway validates this claim when `ValidateLifetime = true`

### Refresh Token

- **Format**: Random 64-byte base64-encoded string
- **NOT a JWT** (opaque token)
- **Stored in**: DynamoDB User record + UserSession
- **Validated by**: Auth Service (not API Gateway)

1. **Start LocalStack**:
```bash
cd C:\Gearify\gearify-umbrella
docker-compose up -d gearify-localstack
```

2. **Start Auth Service**:
```bash
cd C:\Gearify\gearify-auth-svc
dotnet run

```

3. **Start API Gateway**:
```bash
cd C:\Gearify\gearify-api-gateway
dotnet run
# Runs on http://localhost:8080
```

### Test 1: Login and Get Valid Token

```bash
# Login via API Gateway
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -H "X-Tenant-Id: default" \
  -d '{
    "email": "admin@default.com",
    "password": "Admin123!"
  }'
```

**Expected Response**:
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refreshToken": "random-base64-string...",
  "user": {
    "id": "usr_default_admin",
    "email": "admin@default.com",
    "firstName": "Admin",
    "lastName": "User",
    "role": "Admin"
  }
}
```

**Save the token**:
```bash
export ACCESS_TOKEN="eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
export REFRESH_TOKEN="random-base64-string..."
```

### Test 2: Use Valid Access Token

```bash
# Access protected endpoint (example: get current user)
curl -X GET http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "X-Tenant-Id: default"
```

**Expected Response**: `200 OK`
```json
{
  "id": "usr_default_admin",
  "email": "admin@default.com",
  "firstName": "Admin",
  "lastName": "User",
  "role": "Admin"
}
```

**Gateway Logs** (if successful):
```
[Information] JWT token validated for user usr_default_admin in tenant default
```

### Test 3: Test Expired Token

**Option A: Wait 15 minutes**
```bash
# Login
curl -X POST http://localhost:8080/api/auth/login ...
export ACCESS_TOKEN="..."

# Wait 15 minutes and 1 second
sleep 901

# Try to use expired token
curl -X GET http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "X-Tenant-Id: default"
```

**Option B: Change expiry for testing (faster)**

Edit `gearify-auth-svc/appsettings.Development.json`:
```json
{
  "JwtSettings": {
    "AccessTokenExpiryMinutes": 1  // ← Change to 1 minute
  }
}
```

Restart Auth Service, then:
```bash
# Login
curl -X POST http://localhost:8080/api/auth/login ...
export ACCESS_TOKEN="..."

# Wait 61 seconds
sleep 61

# Try to use expired token
curl -X GET http://localhost:8080/api/auth/me \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "X-Tenant-Id: default"
```

**Expected Response**: `401 Unauthorized`
```
(No body or error message)
```

**Response Headers**:
```
Token-Expired: true
```

**Gateway Logs**:
```
[Warning] JWT token expired for request /api/auth/me
```

### Test 4: Refresh the Access Token

```bash
# Use refresh token to get new access token
curl -X POST http://localhost:8080/api/auth/refresh \
  -H "Content-Type: application/json" \
  -H "X-Tenant-Id: default" \
```

**Expected**: `200 OK` ✅

## Troubleshooting

### Issue 1: Tokens Always Rejected

**Symptom**: All tokens return 401, even fresh ones

**Causes**:
1. **Secret mismatch**: API Gateway and Auth Service have different JWT secrets
2. **Issuer mismatch**: Check `Issuer` in both configs
3. **Audience mismatch**: Check `Audience` in both configs

**Solution**:
```bash
# Check Auth Service secret
cat C:\Gearify\gearify-auth-svc\appsettings.json | grep -A 5 JwtSettings

# Check API Gateway secret
cat C:\Gearify\gearify-api-gateway\appsettings.json | grep -A 5 JwtSettings

# They MUST match exactly!
```

### Issue 2: Expired Tokens Still Work

**Symptom**: Tokens work even after 15+ minutes

**Cause**: `ValidateLifetime` is not true or `ClockSkew` is too large

**Check**: `Program.cs:93-94`
```csharp
ValidateLifetime = true,        // Must be true!
ClockSkew = TimeSpan.Zero       // Must be zero or small
```

### Issue 3: No Logs Showing Token Validation

**Symptom**: No logs appear when using tokens

**Cause**: Authentication middleware not added

**Check**: `Program.cs:157-158`
```csharp
app.UseAuthentication();  // Must be present
app.UseAuthorization();   // Must be present
```

### Issue 4: Auth Endpoints Return 401

**Symptom**: Can't login because `/api/auth/login` returns 401

**Cause**: Auth routes require authentication (they shouldn't!)

**Solution**: Auth routes should be anonymous:
```csharp
// In AuthController.cs
[HttpPost("login")]
[AllowAnonymous]  // ← Add this
public async Task<IActionResult> Login([FromBody] LoginRequest request)
```

## Security Considerations

### 1. JWT Secret Management

**Current** (Development):
- Secret hardcoded in `appsettings.json`
- ⚠️ **NOT secure for production**

**Production** (Recommended):
```bash
# Store in environment variable
export JWT_SECRET="your-production-secret-key"

# Or use AWS Secrets Manager
aws secretsmanager get-secret-value --secret-id gearify/jwt-secret
```

Update `appsettings.Production.json`:
```json
{
  "JwtSettings": {
    "Secret": "${JWT_SECRET}"  // Read from environment
  }
}
```

### 2. ClockSkew

**Current**: `TimeSpan.Zero` (no grace period)

**Why**: Strict expiration enforcement

**Alternative**: `TimeSpan.FromMinutes(5)` (allows 5-minute clock drift)

### 3. Token Storage (Client-Side)

**Recommended**:
- Access Token: Memory only (React state, not localStorage)
- Refresh Token: HttpOnly cookie or secure storage

**Why**: Prevents XSS attacks from stealing tokens

### 4. HTTPS

**Production**: Always use HTTPS
- Prevents token interception
- Required for secure cookie transmission

## JWT Validation Flow (Detailed)

```
Request arrives at API Gateway
  │
  ├─ Extract Authorization header
  │  └─ Format: "Bearer <token>"
  │
  ├─ JWT Middleware (Program.cs:97-125)
  │  │
  │  ├─ Parse JWT structure
  │  │  └─ Decode header, payload, signature
  │  │
  │  ├─ Validate Signature (ValidateIssuerSigningKey = true)
  │  │  └─ HMACSHA256(header + payload, secret) == signature?
  │  │     IF NO → 401 Unauthorized
  │  │
  │  ├─ Validate Issuer (ValidateIssuer = true)
  │  │  └─ JWT.iss == "gearify-auth"?
  │  │     IF NO → 401 Unauthorized
  │  │
  │  ├─ Validate Audience (ValidateAudience = true)
  │  │  └─ JWT.aud == "gearify-api"?
  │  │     IF NO → 401 Unauthorized
  │  │
  │  ├─ Validate Lifetime (ValidateLifetime = true)
  │  │  └─ JWT.exp > DateTime.UtcNow?
  │  │     IF NO → 401 Unauthorized + "Token-Expired: true"
  │  │
  │  └─ Extract Claims
  │     └─ Create ClaimsPrincipal with:
  │        - UserId (from "sub")
  │        - TenantId (from "tenantId")
  │        - Role (from "role")
  │        - Email, FirstName, LastName
  │
  ├─ OnTokenValidated Event (Program.cs:112-118)
  │  └─ Log: "JWT token validated for user {UserId}"
  │
  ├─ Attach ClaimsPrincipal to HttpContext.User
  │
  └─ Forward request to downstream service
     └─ Service can access User.Claims
```

## Next Steps

### 1. Add Authorization Policies

Currently, all endpoints allow authenticated users. Add role-based policies:

**Program.cs**:
```csharp
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("AdminOnly", policy =>
    {
        policy.RequireAuthenticatedUser();
        policy.RequireRole("Admin");
    });

    options.AddPolicy("CustomerOnly", policy =>
    {
        policy.RequireAuthenticatedUser();
        policy.RequireRole("Customer");
    });
});
```

**appsettings.json** (routes):
```json
{
  "catalog-route": {
    "ClusterId": "catalog-cluster",
    "AuthorizationPolicy": "Authenticated",  // Require any authenticated user
    "Match": {
      "Path": "/api/catalog/{**catch-all}"
    }
  },
  "admin-route": {
    "ClusterId": "admin-cluster",
    "AuthorizationPolicy": "AdminOnly",  // Admin only
    "Match": {
      "Path": "/api/admin/{**catch-all}"
    }
  }
}
```

### 2. Implement Token Blacklist

For logout, invalidate tokens:
- Store revoked tokens in Redis
- Check on every request
- Auto-expire after original token expiration

### 3. Monitor Failed Authentication

Track failed auth attempts:
- Log to centralized system (Seq, ELK)
- Alert on suspicious patterns
- Implement rate limiting per IP
